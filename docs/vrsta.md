## Pravila
- **Pred združitvijo** seja pogleda to datoteko na svežem `main` (`git fetch origin main && git show origin/main:docs/vrsta.md`). Združi samo, če je njen pull request prvi v vrsti ali ga v vrsti ni in pred njim ni nikogar, ki je pripravljen (zelen na GitHubu).
- **Nov pull request, pripravljen za `main`**, se vpiše na konec vrste (vrstica v tabeli spodaj, s potiskom te datoteke v svoj pull request ali z drobnim pull requestom samo s to datoteko) in ostane osnutek (pravilo »Osnutek do vrste« spodaj). Hitri popravki rdečega `main` gredo na začetek.
- **Po združitvi** seja svojo vrstico izbriše (v naslednjem potisku na `main` ali to stori koordinacija »VSE SEJE«) in pošlje sporočilo naslednjemu v vrsti, če pozna njegovo sejo.
- Koordinacija vsakega računa (»VSE SEJE«) vrsto sproti ureja; vrstni red med računi se dogovori tu, ne v pogovoru. Pri sporu v tej datoteki obdrži vrstice obeh strani.
- **Skupine in zbirne veje** (odločitev uporabnika 7. 11. 2026, tabla #382): več sorodnih osnutkov gre na `main` kot ena zbirna veja (`zbirna/<ime>`, en pull request, en krog testov). Vodja skupine spoji svež `main`, razreši spore (`index.html` in `garaza.html` z `node tools/stamp.js --merge`), požene `npm run test:related` in `node tools/stamp.js --check` ter v opisu navede člene in predaje iz njihovih opisov. Originalne pull requeste zapre šele, ko je zbirna veja na `main`. V tabeli ima skupina svojo vrstico in pod njo člene (5a, 5b …); po združitvi se izbrišejo vse. Del skupine, ki pade in ga ni mogoče hitro popraviti, gre ven in se vrne na svoje mesto (kot pri zbirni B). **Proge so v vrsti vedno zadnje**: pull request, ki ni proga, se vpiše pred njih; izdelava novih prog teče naprej, na konec gre samo njihov pull request.
- **Osnutek do vrste** (odločitev uporabnika 4. 11. 2026): »Ready for review« imata samo prva dva v vrsti, vsi drugi pull requesti vseh računov so osnutki, tudi ko je delo končano. Tako testi na GitHubu tečejo samo za ta dva: GitHub zmore hkrati približno dva cela kroga, z več krogi hkrati pa krog traja ~3,5 h namesto ~1,5 h. Ko pull request pride med prva dva, ga njegova seja označi »Ready for review« (znak ji da koordinacija), ko je prvi in zelen, ga po pravilu »Svež main pred združitvijo« (`CLAUDE.md`) združi. Pull request, ki je označen, a ni med prvima dvema, koordinacija kateregakoli računa vrne v osnutek in v komentarju napiše, zakaj.
- **Prevzem zdaj: prevzem dela, ko računu zmanjka porabe** (odločitev uporabnika 4. 11. 2026): račun, ki mu bo zmanjkalo tedenske porabe, se dogovori, kateri račun ga nadomesti (»prevzame račun N«). Pred ustavitvijo vsaka njegova seja v opis svojega pull requesta zapiše kratko predajo (stanje, kaj manjka, kako testirati), končan pull request vpiše na konec vrste s pripisom »prevzame račun N« (ostane osnutek), se odjavi od dogodkov pull requesta in se ustavi; novih tem ne začenja. Seja za združevanje računa N (Sonnet, `docs/varcevanje.md`) te pull requeste po vrsti pripelje na `main` kot svoje: svež `main`, spori, lokalni povezani testi, »Ready for review«, ko so med prvima dvema, testi na GitHubu, združitev. Na tujo vejo samo potiska (spoj `main`, popravek), zgodovine ne prepisuje. Večje popravke kode dela samo, če ima račun N dovolj porabe, sicer pull request pusti v vrsti z opombo, kaj manjka. Ko se poraba obnovi, nove seje prvega računa nadaljujejo po predajah; kar je medtem prišlo na `main`, je opravljeno.
