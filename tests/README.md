# Testi

Samodejni testi za igro. Igra sama ne potrebuje namestitve; testi potrebujejo le Node.js (22) in za teste
v brskalniku Playwright (`npm install` ga namesti, `npx playwright install chromium` prenese brskalnik).
Opisi prog, ki jih testi preverjajo, so v `docs/proge/<id>.md`, opis igre po temah v `docs/igra.md` (prej oboje v `README.md`).

```sh
npm install          # enkrat
npm test             # vse (~90 min)
npm run test:node    # samo fizika, AI, dirke in prvenstvo (~4 min)
npm run test:browser # samo testi v brskalniku (~75 min s programskim WebGL)
npm run test:fleet   # samo vozni park: izrisovalni komplet, register vozil, vožnja, uničenje, AI in izris vseh vozil (~8 min)
node tests/run.js browser --shard 2/4         # en del brskalniških testov (kot na GitHubu)
node tests/run.js browser --shard 2/4 --list  # samo izpiše, kateri testi so v tem delu
npm run test:related # samo testi, povezani s spremembami proti main (tih izpis: samo napake in povzetek)
node tests/run.js --related --files js/lang.js,docs/proge/spa.md --list  # kateri testi spadajo k tem datotekam
node tests/run.js node --quiet                 # tih izpis: napake padlih testov in povzetek
```

`--related` (`npm run test:related`) izbere teste iz datotek, spremenjenih proti `main` (`git diff` od skupnega commita z `origin/main` ali
`main`, z neshranjenimi in novimi datotekami; pred tem `git fetch origin main`): test z istim imenom ali delom imena (`js/tracks/spa.js`,
`docs/proge/medvode.md` → `medvode`, `medvode-props`, `browser/medvode-castle` …; `js/world-montreal.js` → `montreal`, `world`), spremenjen
test sam in teste iz kratkega seznama `RELATED` v `tests/run.js` za velike skupne datoteke (`js/core.js`, `js/game.js`, `js/render.js` …).
`--quiet` ne izpiše ničesar za uspešen test; za padlega izpiše vrstice FAIL in zadnje vrstice (sled sklada), na koncu povzetek.

**Hiter vstop** (za teste in orodja): naslov `index.html?proga=<id>&nacin=<način>&t=<s>&vreme=suho|dez&avto=<id>&seme=<n>` odpre igro naravnost
na dirki (brez menija, preleta in kvalifikacij). `nacin`: `dirka`, `kronometer`, `promet`, `policija` (ali `race`, `tt`, `traffic`,
`police`), samo načini, ki jih proga ima; `t`: dirka na avtopilotu do `t` s po štartu, nato pavza; `avto`: id vozila (`js/cars/<id>.js`).
Način, vreme in avto se nastavijo kot v meniju. Napačen del javi obvestilo »Hitri vstop: neveljavno …«. Branje naslova: `Core.quickArgs`,
v igri `quickGo` v `js/game.js`; `window.__game.quick` pove, kaj je naslov zahteval in ali je dirka že tam (`done`).

**Testni način (ponovljive dirke):** hiter vstop vklopi testni način za ves obisk. Seme dirke je `seme` (celo število od 1, privzeto 1)
in vsi naključni dogodki, ki spremenijo dirko (kolo odpade, razbitine, predrta guma, reakcije in napake AI, vreme, ki ga nastavitve
prepustijo naključju, čakanje luči pred štartom), so iz njega: isti naslov dvakrat da isto dirko in enak posnetek, ne glede na
`Math.random`. Tudi ponovni začetek dirke v istem obisku je ista dirka. V Node testih to naredi `repro: true` v nastavitvah `Core.Race`.
Vizualni učinki (dim, iskre, komentar) ostanejo naključni. `window.__game.repro` pove seme, `window.__game.recSum()` povzetek posnetka.
**Posnetki pred/po** (`tools/shot.mjs`, prek hitrega vstopa): `node tools/shot.mjs bathurst --m 1284` postavi avto na idealno linijo 1284 m po
štartu (`s` iz poročila o napaki), skrije druge avte in shrani pogled kamere za avtom brez HUD-a, pokonci (360 × 640) in ležeče (640 × 360);
`--pokonci` ali `--lezece` samo enega, `--m 400,1284` več mest, `--t <s>` mesto, kamor pride avtopilot (s tekmeci), `--vreme dez`.
`--pred main` (ali drug ref ali mapa s kopijo igre) posname ista mesta še v drugi različici in naredi `…-primerjava.png` (pred | po | razlika,
spremenjeni piksli vijolični) ter `povzetek.md` z deležem spremenjenih pikslov; ista koda da pod 0,5 % (gledalci, zastave). Slike so v
`test-results/shots/`. Za primerjavo vzemi pravo progo (`CLAUDE.md`). `--nabor` je nabor za pull requeste (`NABOR` v orodju in prave proge,
katerih datoteke sprememba spreminja): na GitHubu ga ob pull requestu, ki spremeni igro, požene `.github/workflows/posnetki.yml`
(»Posnetki pred/po«, ~5 min): slike so v artefaktu `posnetki-<št>`, povzetek v povzetku posla. Ne šteje kot test: rdeč je le, ko igra na veji javi napako.

**Datoteka s posnetkom** (`tools/posnetek.mjs`, sklop 12 orodja za napake): uporabnik v Nastavitvah orodja (Posnetek dirke → Shrani) ali ob
zbirki (Shrani posnetek (.rrp)) shrani posnetek dirke `posnetek_<proga>_<LLLLMMDD-UUMM>.rrp` in ga pošlje. `node tools/posnetek.mjs <datoteka>`
ga odpre v igri v brskalniku brez zaslona in izpiše progo, način, različico (in ukaz `git log -S`, če ni ista kot tu), napravo, zastavice
dirke, samodejne zastavice (kje je bil tisti avto), dnevnik in besedilo poročila; `--t 41.3,00:52.1` naredi slike posnetka ob teh časih
(`--avto ti|<k>`, `--kamera chase|tv`, `--pokonci`, `--lezece`), `--zastavice` ob vsaki zastavici. Izhod: `test-results/posnetki/<ime>/`
(`povzetek.txt`, `povzetek.json`, slike). Datoteke in slik ne shranjuj v repozitorij.

**Predogled pred mainom** (`.github/workflows/stran.yml`, `tools/predogled.mjs`): stran na GitHub Pages ima `main` v korenu, vsak odprt pull
request iz tega repozitorija (največ 3 najnovejši) pa v `beta/<številka>/`; seznam je na `…/dirkaska-igra/beta/`. Stran se zgradi znova ob
vsaki spremembi `main` in ob odprtju, spremembi ali zaprtju pull requesta. Deluje, ko je v Settings → Pages → Source izbrano »GitHub Actions«
(do tedaj ostane objava z veje `main`, potek pa to samo javi). Predogled ima svoj service worker, shranjene nastavitve in napredek pa deli z glavno igro.

Na GitHubu se ob vsakem pull requestu in vsaki spremembi veje `main` samodejno poženejo vsi testi
(`.github/workflows/tests.yml`). Test, ki teče dlje od 15 minut, se ustavi in šteje kot neuspešen
(drugače: `TEST_TIMEOUT_MIN=30 npm test`; na GitHubu brskalniški testi tečejo s 30 minutami na test); test pomnilnika (`browser/memory.test.mjs`), ki gre trikrat skozi vse proge in se z vsako novo progo podaljša, ima trikrat toliko časa, smoke in perf pa dvakrat (na GitHubu 90 in 60 minut).

Brskalniški testi na GitHubu tečejo na štirih strojih hkrati (posli »Igra v brskalniku (1/4)« do »(4/4)«, vsak do 120 minut, več kot omejitev testa pomnilnika),
posel »Igra v brskalniku« pa je zelen, ko so zeleni vsi štirje deli. `tests/run.js --shard k/4` razdeli teste po tem, koliko časa traja
vsak na GitHubu (tabela `SECS` v `tests/run.js`; test, ki ga ni v tabeli, šteje 60 s): najdaljši najprej, vsak v del, ki ima do tedaj
najmanj časa. Na hitrem stroju traja vsak del ~26 min, na počasnem do dvakrat dlje (prej je celoten nabor na enem stroju trajal
od ~105 do več kot 180 min). Ko se kak test zelo podaljša (smoke, memory, perf, gfx in world z vsako progo), popravi njegov čas v
`SECS` po povzetku zadnjega zagona, da ostanejo deli enako dolgi.

## Referenčne vrednosti

Datoteke v `golden/` so posnetek pravilnega obnašanja. Če spremembo naredimo **namenoma** (npr. uglasimo fiziko ali
dodamo drevesa na progo), jih osvežimo z `npm run golden:update` in spremembo razložimo v commitu. Pri preurejanju
kode brez sprememb obnašanja se ne smejo spremeniti.

Z `GAME_ROOT=/pot/do/druge/kopije` lahko teste poženemo na drugi kopiji igre (npr. starejši različici).
